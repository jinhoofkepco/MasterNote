# MasterNote S Pen UI interaction design

이 문서는 펜 메뉴의 위치, 입력 영역, 물리 버튼, 도구 선택, 지우개 처리에 대한 구현 계약이다.
반복적인 좌표 보정으로 서로 다른 동작이 다시 깨지지 않도록, 화면에 보이는 모양과 입력 판정을
같은 기하 모델에서 계산하는 것을 목표로 한다.

## 1. 확정된 동작

- 원호의 왼쪽 시작점은 `180°`, 끝점은 `280°`, 전체 각도는 `100°`다.
- 원호 중앙 방향은 `230°`다.
- S Pen 물리 버튼을 누른 실제 펜 촉 좌표는 원호 중심이 아니다. 원호 중앙 방향에서
  `0.66a`만큼 떨어진 내부 앵커가 된다.
- 메뉴 입력 영역은 `a..b` 원환 부채꼴과 도구별 `b..c` 돌출 영역뿐이다.
- 위 영역 밖은 투명한 메뉴 영역이 아니라 일반 문제지 영역이다. 펜 입력은 문제지로 그대로
  전달되며, 첫 `DOWN`을 잃어서는 안 된다.
- 메뉴가 열린 뒤에는 S Pen 물리 버튼을 화면 어디에서 눌러도 메뉴가 닫힌다.
- `페이지 맞춤`과 `학생/선생 전환` 기능은 코드에 남기되 펜 메뉴에서는 보이지 않는다.
- 지우개를 누르고 이동하는 동안에는 삭제 후보 영역만 표시한다. 실제 삭제 연산은 펜을 뗀
  `ACTION_UP` 이후에 한 번만 시작한다.

## 2. 좌표계와 a/b/c

Android 화면 좌표처럼 오른쪽이 `+x`, 아래쪽이 `+y`다. 각도는 현재 Compose 배치와 동일하게
`cos`, `sin`으로 계산한다. 따라서 `180°`는 왼쪽이고 `270°`는 위쪽이다.

기호는 다음과 같다.

- `P`: 물리 버튼을 누른 순간의 실제 S Pen 촉 화면 좌표
- `O`: 원호 중심
- `S = 180°`: 원호 시작각
- `T = 100°`: 원호 전체 각도
- `E = S + T = 280°`: 원호 끝각
- `M = S + T / 2 = 230°`: 원호 중앙각
- `u = (cos(M), sin(M))`: 원호 중앙을 향하는 단위 벡터
- `R`: 메뉴 항목 중심이 놓이는 반지름
- `D`: 논리 슬롯 지름. `max(toolButtonSize, minimumTouchSize)`를 사용한다.
- `L`: 펜이 선택 또는 호버됐을 때 추가로 뽑히는 거리

세 반지름은 반드시 하나의 식으로 계산한다.

```text
a = R - D / 2
b = R + D / 2
c = b + L
```

- `a`: 메뉴 입력 영역과 도구 reveal viewport가 시작되는 반지름
- `b`: 일반 버튼 영역의 바깥쪽 끝이자, 쉬고 있는 도구의 팁 반지름
- `c`: 호버되거나 선택된 도구의 팁 반지름

물리 버튼 좌표와 원호 중심의 관계는 다음을 불변 조건으로 사용한다.

```text
P = O + u * (0.66a)
O = P - u * (0.66a)
```

따라서 펜 촉에서 메뉴 안쪽 경계까지 남는 거리는 중앙선 기준 `0.34a`다. 위치 보정 코드는
`P`를 원호 중심으로 사용하거나 별도의 경험값을 더해서는 안 된다.

## 3. 항목 배치

항목 수가 `N`일 때 인덱스 `i`의 각도와 중심은 다음과 같다.

```text
step = T / (N - 1)
theta(i) = S + i * step
center(i) = O + R * (cos(theta(i)), sin(theta(i)))
```

인접한 논리 슬롯 사이에 `gap`이 확보되도록 `R`을 계산한다.

```text
R = max(
    radialMinRadius,
    (D + gap) / (2 * sin(step / 2))
)
```

`RadialFan`의 부모 슬롯도 `D`로 측정해야 한다. 폰에서 시각 크기 `44dp` 안에 `48dp` 입력
영역을 넣은 뒤 부모의 `44dp` 제약으로 다시 줄이는 현재 형태를 허용하지 않는다. 시각 요소가
`D`보다 작으면 `D` 슬롯 안에서 중앙 정렬한다.

### 메인 메뉴 항목

인덱스 계산을 조건문으로 이어 붙이지 않고 명시적인 항목 목록을 만든다.

학생 화면, 6개:

1. 실행 취소
2. 지우개
3. 펜
4. 형광펜
5. 색상
6. 다시 실행

선생 화면, 7개:

1. 실행 취소
2. 지우개
3. 펜
4. 형광펜
5. 색상
6. 채점
7. 다시 실행

`resetZoom`과 `toggleTeacherMode` 함수 및 호출 가능 경로는 삭제하지 않는다. 다만 위 항목
목록에는 넣지 않는다.

### 보조 페이지

메인, 색상, 펜 설정 페이지는 같은 중심 `O`를 사용한다. 페이지가 바뀔 때 중심이 움직이면
물리 버튼 좌표와 메뉴의 관계가 깨져 보이므로 금지한다. 페이지별 항목 수에 따라 `R`을 다르게
계산할 수 있지만, 전체 overlay bounds는 모든 페이지의 최대 범위를 미리 포함해야 한다.

색상 페이지는 현재 `7색 + 뒤로 = 8개`다. 기하 계산의 `itemCount`도 반드시 8이어야 한다.
펜 설정 페이지를 100도 영역에 넣을 때는 굵기 항목과 투명도 원호의 시작각, 끝각을 같은
`180°..280°` 계약 안에서 함께 계산한다. 메인 원호만 100도로 바꾸고 투명도 원호를 기존
`300°`까지 남겨두지 않는다.

## 4. 극좌표 hit test

화면 좌표 `X`를 원호 중심 기준으로 변환한다.

```text
d = X - O
r = hypot(d.x, d.y)
angle = normalizedDegrees(atan2(d.y, d.x))
inSector = clockwiseDelta(S, angle) <= T
```

기본 메뉴 영역은 다음 원환 부채꼴이다.

```text
ringHit = inSector && a <= r && r <= b
```

첫 항목과 마지막 항목의 중심은 각각 정확히 `S`, `E`에 놓이므로 원형 48dp 입력 영역의
절반이 각도 경계 밖에 걸친다. 보이는 버튼을 잘라내지 않도록 각 항목의 원형 hit disk도
`ringHit`에 합친다. 이는 반지름 `a..b` 계약을 넓히는 것이 아니라 끝점 버튼의 접선 방향
영역을 보존하기 위한 것이다.

버튼 사이의 빈틈도 `a..b` 안에서는 메뉴 영역이다. 빈틈을 누르면 기능은 실행하지 않지만
이벤트는 소비하여 아래 문제지에 점이 찍히지 않게 한다.

도구 항목은 각 도구의 방향 벡터 `ui`와 접선 벡터 `vi`를 사용한다.

```text
radial = dot(d, ui)
tangential = abs(dot(d, vi))
extensionHit = b < radial && radial <= c && tangential <= D / 2
```

`extensionHit`은 선택된 도구 하나에만 만들지 않는다. 펜, 형광펜, 지우개, 채점 도구 모두에
항상 `b..c`의 안정된 입력 영역을 예약한다. 그래야 아직 뽑히지 않은 도구의 바깥쪽에 펜을
처음 가져가도 호버를 시작할 수 있고, 애니메이션 중 입력 영역이 움직이지 않는다.

최종 판정은 다음과 같다.

```text
isPenUi(X) = ringHit || anyItemHitDisk(X) || anyToolExtensionHit(X)
```

- `isPenUi == true`: 메뉴 host가 이벤트를 받고 해당 버튼 또는 메뉴 빈틈을 처리한다.
- `isPenUi == false`: 일반 문제지 입력으로 전달한다.
- 기존의 `r < dismissRadius` 내부 닫기 부채꼴은 제거한다. `r < a`는 일반 문제지다.

## 5. same-window overlay

별도 Compose `Popup`은 사각형 Window를 만든다. 사각형 안의 투명한 픽셀에서 이벤트를
소비하지 않더라도 같은 `DOWN`을 아래 Activity의 `InkInputView`로 안정적으로 통과시킬 수
없다. 따라서 이번 계약은 펜 메뉴를 Activity와 같은 View 계층의 overlay로 배치하는 것을
전제로 한다.

권장 구조:

```text
Reader root FrameLayout
  PDF / DryInkView / InkInputView
  Top chrome
  StylusMenuHostView (same window, topmost)
```

`StylusMenuHostView`는 화면 전체 또는 계산된 envelope를 차지할 수 있지만, raw event 좌표에
대해 `isPenUi`가 참일 때만 Compose 메뉴로 dispatch한다. 거짓이면 `false`를 반환하여 아래
`InkInputView`가 같은 이벤트를 받게 한다.

메뉴가 열린 상태에서 일반 영역에 S Pen `ACTION_DOWN`이 오면 다음 순서를 지킨다.

1. raw 좌표로 `isPenUi`를 판정한다.
2. 거짓이면 메뉴 상태를 즉시 닫힘으로 바꾼다.
3. 같은 `ACTION_DOWN`을 `super.dispatchTouchEvent`로 계속 전달한다.
4. `InkInputView`가 그 `DOWN`부터 정상 스트로크를 시작한다.

Compose recomposition이 끝날 때까지 기다렸다가 이벤트를 전달하면 첫 점 또는 전체 스트로크를
잃을 수 있다. host의 활성 상태와 hit geometry는 Activity가 즉시 읽을 수 있는 상태여야 한다.

호버가 메뉴 영역과 일반 영역의 경계를 넘을 때도 같은 공간 판정을 사용한다. 메뉴 쪽에는
필요한 `HOVER_ENTER/MOVE/EXIT`가 전달되고, 일반 영역에서는 `InkInputView`의 현재 도구
미리보기가 계속 동작해야 한다.

## 6. 물리 버튼 상태 머신

same-window 구조에서는 Activity의 중앙 처리기가 모든 S Pen 물리 버튼 이벤트를 먼저 본다.
Activity와 Popup listener가 각각 latch를 소유하는 구조를 사용하지 않는다.

상태는 최소한 다음 세 가지를 구분한다.

```text
CLOSED
OPEN_WAITING_FOR_OPENING_RELEASE
OPEN_ARMED
```

- `CLOSED`에서 버튼 상승 edge: `P`를 저장하고 메뉴를 연 뒤
  `OPEN_WAITING_FOR_OPENING_RELEASE`로 이동한다.
- 여는 버튼을 계속 누르고 있는 동안에는 닫기 동작을 실행하지 않는다.
- 버튼 release: `OPEN_ARMED`로 이동한다.
- `OPEN_ARMED`에서 다음 버튼 상승 edge: 펜 위치와 관계없이 메뉴를 닫고 `CLOSED`로 이동한다.
- 메뉴 항목 선택이나 일반 영역 `DOWN`으로 메뉴가 닫혀도 latch를 `CLOSED` 상태와 일치시킨다.

Samsung 기기에서 물리 버튼 이벤트 좌표가 유효하지 않은 경우를 위해 마지막 정상
`ACTION_HOVER_MOVE`의 raw S Pen 좌표를 저장한다. 버튼 event의 좌표가 유효하면 그것을 우선
사용하고, 그렇지 않을 때만 저장 좌표를 사용한다.

`BUTTON_STYLUS_PRIMARY`와 `BUTTON_STYLUS_SECONDARY`를 현재처럼 동일한 메뉴 버튼으로
취급할 수 있지만, mask 판정과 rising/release edge 판정은 중앙 처리기 한 곳에만 둔다.

## 7. 도구 reveal과 선택 상태

각 도구 이미지에는 이미지 상단에서 실제 팁까지의 보정값이 있다. 렌더링은 해당 보정값과
`a/b/c`만 사용한다.

```text
viewport start = a
viewport end = c
resting tip = b
hovered tip = c
selected tip = c
```

- 기본 상태의 팁은 정확히 `b`에서 끝난다.
- 호버된 도구는 팁이 `c`까지 이동한다.
- 클릭하여 선택된 도구는 메뉴를 다시 열었을 때도 `c`에 고정된다.
- 선택된 도구에 다시 호버하면 팁 반지름은 `c`를 넘지 않는다. 확대는 `c`를 고정한 transform
  origin으로 적용한다.
- 지우개 PNG의 투명 여백과 폭 보정도 별도 퍼센트 이동이 아니라 같은 팁 앵커 모델을 사용한다.

overlay bounds는 모든 페이지, 모든 도구의 `c`, 호버 확대, 이미지의 접선 방향 폭과 그림자를
합친 union으로 계산한다. 메인 페이지 크기만으로 root를 측정하여 색상 또는 펜 설정 페이지를
잘라서는 안 된다.

## 8. 지우개 처리

지우개 제스처는 `PREVIEW`와 `COMMIT`으로 분리한다.

### DOWN/MOVE: PREVIEW

- canonical 좌표로 지우개 경로만 수집한다.
- 화면에는 반경과 지나간 후보 영역을 표시한다.
- `AnnotationDocument`, operation log, undo stack, attempt 상태를 변경하지 않는다.
- LAN operation을 만들거나 전송하지 않는다.
- 이동 중 같은 획에 대해 반복적으로 삭제 교차 연산을 수행하지 않는다.

### UP: COMMIT

1. 수집한 경로를 고정된 immutable snapshot으로 만든다.
2. `ACTION_UP` 이후에 한 번만 삭제 교차 연산을 시작한다.
3. 현재 author, attempt, partial/whole 조건을 한 번 적용한다.
4. 결과 operation을 한 묶음으로 저장하고 undo 단위도 한 번만 만든다.
5. 로컬 반영과 LAN 동기화를 기존 operation 순서 계약에 맞춰 수행한다.
6. 성공 또는 실패가 확정된 뒤 preview를 제거한다.

`ACTION_CANCEL`, 멀티포인터 전환, 페이지 변경, Activity 중단에서는 preview와 수집 경로만
버리고 삭제 operation을 만들지 않는다.

연산이 오래 걸릴 수 있으므로 UI thread에서 큰 교차 연산을 실행하지 않는다. 다만 새 지우개
제스처, undo, 페이지 이동과 순서가 뒤바뀌지 않도록 문서 mutation mutex 또는 동일한 직렬화
경로를 사용한다. 제출되어 잠긴 학생 회차처럼 실제 삭제가 허용되지 않는 상태에서는 처음부터
preview를 금지하거나, 금지 상태임을 명확히 표시해야 한다. 지워질 것처럼 보인 뒤 아무 변화가
없는 상태를 만들지 않는다.

## 9. 폰/태블릿 기준 수치

다음 값은 현재 토큰을 사용한 계산 기준이다.

- 폰: `D=48dp`, `gap=2dp`, `L=20dp`, `radialMinRadius=96dp`
- 태블릿: `D=54dp`, `gap=4dp`, `L=24dp`, `radialMinRadius=124dp`

| 기기/역할 | N | step | R | a | b | c | 0.66a |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 폰 학생 | 6 | 20.000° | 143.97dp | 119.97dp | 167.97dp | 187.97dp | 79.18dp |
| 폰 선생 | 7 | 16.667° | 172.49dp | 148.49dp | 196.49dp | 216.49dp | 98.01dp |
| 태블릿 학생 | 6 | 20.000° | 167.00dp | 140.00dp | 194.00dp | 218.00dp | 92.40dp |
| 태블릿 선생 | 7 | 16.667° | 200.09dp | 173.09dp | 227.09dp | 251.09dp | 114.24dp |

표의 값은 화면에 직접 하드코딩하지 않는다. 토큰과 순수 기하 함수로 매번 계산하고 테스트에서
허용 오차 내 결과만 검증한다.

## 10. 화면 가장자리 예외

먼저 `O = P - u * 0.66a`로 이상적인 위치를 계산한다. 이후 전체 overlay envelope가 safe
window bounds를 벗어날 때만 메뉴 전체를 평행 이동하여 화면 안으로 clamp한다.

- 일반 위치에서는 `P = O + u * 0.66a`를 정확히 유지한다.
- 가장자리 clamp에서는 화면 잘림 방지를 우선하며, 이때만 `0.66a` 관계의 오차를 허용한다.
- 각 항목을 개별적으로 이동하거나 각도와 반지름을 바꾸지 않는다.
- clamp 이후에도 모든 항목은 동일한 `O`, `R`, `a/b/c`를 공유한다.
- 시스템 바와 cutout inset을 safe bounds에 포함한다.

가장자리 보정이 적용됐는지는 debug overlay에서 이상적 중심과 실제 중심을 함께 표시할 수 있게
한다. 실기기 조정값을 일반 위치 공식에 섞지 않는다.

## 11. 구현 순서

1. 부작용 없는 순수 기하 모델과 hit-test 함수를 추가한다.
2. `a/b/c`, 100도 각도, 항목 목록을 단위 테스트로 먼저 고정한다.
3. 별도 Popup을 same-window menu host로 교체하고 outside pass-through를 완성한다.
4. 물리 버튼을 Activity의 단일 상태 머신으로 통합한다.
5. 메인 메뉴에서 역할 전환과 페이지 맞춤 시각 항목을 제거한다.
6. `ToolPenButton`의 viewport, tip anchor, 모든 도구 extension hit를 새 기하에 연결한다.
7. 색상과 펜 설정 페이지를 같은 중심 및 전체 bounds 계약으로 옮긴다.
8. 지우개를 preview/commit 단계로 분리한다.
9. 자동 테스트를 통과시킨 뒤 폰과 태블릿 실기기에서 호버, 버튼, 지우개를 확인한다.

각 단계는 바로 다음 단계로 넘어가기 전에 독립적으로 빌드 및 테스트한다. 토큰 수치 조정은
입력 구조와 저장 동작이 고정된 이후에만 수행한다.

## 12. 회귀 테스트

### 순수 단위 테스트

- `S=180°`, `E=280°`, `M=230°`인지 확인한다.
- `P-O`의 각도가 `230°`, 길이가 `0.66a`인지 폰/태블릿 모두 확인한다.
- 모든 구성에서 `0 < a < b < c`인지 확인한다.
- 첫 항목은 `180°`, 마지막 항목은 `280°`이고 중간 항목 간격이 일정한지 확인한다.
- 학생 항목은 6개, 선생 항목은 7개이며 reset/role 항목이 없는지 확인한다.
- 일반 도구의 팁이 기본 `b`, 호버 `c`, 선택 `c`인지 확인한다.
- 지우개를 포함한 모든 도구가 같은 반지름 기준으로 정렬되는지 확인한다.
- `a`, `b` 경계는 ring hit이고 `a-epsilon`, tool이 아닌 방향의 `b+epsilon`,
  `c+epsilon`, sector 밖은 일반 영역인지 확인한다.
- 모든 도구 방향에서 `b..c` extension이 hit이고 접선 폭 밖은 일반 영역인지 확인한다.
- 색상 페이지 기하의 항목 수와 실제 렌더 항목 수가 모두 8인지 확인한다.
- 모든 페이지와 hover scale을 포함한 요소가 계산된 overlay bounds 안에 있는지 확인한다.

### Android 통합 테스트

- 물리 버튼 한 번으로 메뉴가 열리고, 여는 버튼을 계속 누르고 있어도 즉시 닫히지 않는다.
- release 뒤 두 번째 물리 버튼으로 메뉴가 닫힌다.
- 중앙 내부, 링, 도구 돌출부, overlay 사각형의 투명 영역, 화면 모서리 어디에서 눌러도
  물리 버튼으로 메뉴가 닫힌다.
- `r<a` 일반 영역의 첫 stylus `DOWN`이 메뉴를 닫고 같은 위치에서 스트로크를 시작한다.
- `a..b`의 버튼 사이 빈틈은 스트로크를 만들지 않는다.
- 아직 선택되지 않은 각 도구의 `b..c`에 처음 호버해도 도구가 뽑힌다.
- 선택한 펜은 메뉴를 닫았다 다시 열어도 `c`에 고정된다.
- `페이지 맞춤`, `학생 모드`, `선생 모드` 설명을 가진 펜 메뉴 버튼이 표시되지 않는다.
- 기존 reset/role 함수 자체와 다른 호출 경로는 정상 동작한다.
- 지우개 DOWN/MOVE 중 snapshot revision, undo, operation log, LAN 송신 횟수가 변하지 않는다.
- 지우개 UP 이후에만 revision과 operation이 정확히 한 번 변한다.
- 지우개 CANCEL에서는 어떤 operation도 생성되지 않는다.
- 문제지 확대 상태에서도 preview 경로와 실제 삭제 경로가 canonical 좌표에서 일치한다.
- 화면 가장자리에서 전체 메뉴가 safe bounds 안에 있고 항목 간 `a/b/c` 정렬이 유지된다.

### 실기기 확인

- Galaxy S23 Ultra 세로 화면
- Galaxy Tab S11 세로 화면
- S Pen hover enter/move/exit
- 물리 버튼 press/hold/release/repress
- 펜, 형광펜, 지우개, 채점 선택과 선택 상태 유지
- 긴 지우개 경로를 그리는 동안 프레임 저하가 없고, UP 뒤 결과가 한 번에 반영되는지 확인

## 13. 완료 조건

- 일반 위치에서 실제 펜 촉 `P`가 항상 원호 중앙 방향의 `0.66a`에 놓인다.
- 메뉴 UI는 `a..b`와 도구별 `b..c`에만 반응한다.
- 나머지 영역에서 문제지 필기의 첫 점이 유실되지 않는다.
- 물리 버튼 두 번째 press가 펜 위치와 무관하게 메뉴를 닫는다.
- 메인 메뉴는 학생 6개, 선생 7개이고 100도 안에서 일정한 간격으로 정렬된다.
- 모든 도구가 기본 `b`, 호버/선택 `c` 기준으로 정렬된다.
- 지우개는 이동 중 표시만 하고 `ACTION_UP` 이후에 한 번만 삭제한다.
- 폰과 태블릿의 화면 가장자리에서도 메뉴가 잘리지 않는다.
